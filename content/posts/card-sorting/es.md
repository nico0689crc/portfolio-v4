El [tree testing](/es/blog/tree-testing-arquitectura-informacion) que documenté en otro artículo tiene un requisito previo incómodo: necesitás tener ya un árbol de categorías para testearlo. Card sorting es lo que hago **antes**, cuando todavía no sé cómo agrupar nada.

## La técnica de card sorting, sin vueltas

Le doy a cada participante un mazo de tarjetas. Cada una tiene el nombre de un contenido o producto real —no una categoría, un ítem específico. Le pido que las agrupe como tenga sentido para ella, y después que le ponga un nombre a cada grupo que armó.

Eso es todo el experimento. Lo interesante nunca es la instrucción, es lo que la gente hace con ella cuando nadie le dice cómo agrupar.

## Abierto vs. cerrado

**Card sorting abierto:** la persona arma sus propios grupos y les pone el nombre que quiera. Sirve cuando no tengo ninguna estructura previa y quiero descubrir qué categorías tienen sentido desde cero. Es el que más sorprende, porque no hay ninguna categoría sugerida que pueda influir la respuesta.

**Card sorting cerrado:** le doy las categorías ya definidas y le pido que ubique cada tarjeta en una de ellas. Sirve para validar una estructura que ya armé, antes de pasar al tree testing formal. Es un paso intermedio entre "no tengo estructura" y "quiero testear la estructura que ya tengo".

Casi siempre empiezo con uno abierto. Si ya tengo una hipótesis fuerte de estructura, uso uno cerrado para confirmarla más rápido.

## Lo que casi siempre sale distinto de lo esperado

La sorpresa más común no es qué tarjetas se agrupan juntas —eso suele coincidir bastante con la intuición. Es **cómo se llaman los grupos**. Es exactamente el mismo tipo de hallazgo que documenté con la categoría "Software" en Mexx: la gente agrupa productos de forma razonable, pero el nombre que le pone al grupo casi nunca coincide con el catálogo interno de la empresa.

Ese es el valor real de la técnica: no organiza la información por vos. Te muestra el vocabulario con el que la gente ya piensa esa información, para que la estructura hable ese idioma en vez del tuyo.

## Cuántas personas hacen falta

Entre 15 y 20 para un sorting abierto, más que las 10 que suelen alcanzar para una encuesta o un tree test. La razón es que acá no hay una tarea con éxito o fracaso que medir. Hay patrones de agrupación que necesitan repetirse varias veces antes de que se pueda confiar en que son un patrón real, y no una coincidencia de un par de personas con el mismo criterio.

## Herramientas

Uso las mismas —[UXTweak](https://www.uxtweak.com/), [Optimal Workshop](https://www.optimalworkshop.com/)— que para tree testing. Ambas ofrecen las dos técnicas en la misma plataforma, pensadas para complementarse: primero se sortea para descubrir grupos, después se testea el árbol resultante para confirmar que funciona.

## Dónde entra en el proceso completo

Card sorting va antes que [tree testing](/es/blog/tree-testing-arquitectura-informacion), en la etapa de definición de [mi proceso de diseño](/es/blog/como-diseno-una-interfaz-desde-cero). El orden importa: sortear primero da la estructura candidata, testear después confirma si esa estructura realmente se navega bien.

Saltarse el sorting y adivinar la estructura de entrada significa testear una hipótesis que nunca se contrastó contra cómo la gente agrupa las cosas en su cabeza. Cuando esa hipótesis falla, hay que rehacer la estructura después del tree test. Eso es exactamente el trabajo doble que estas dos técnicas, usadas en orden, existen para evitar.

Es tentador saltarse el paso del sorting cuando el plazo del proyecto es corto, porque se siente como una tarea de investigación más y no como parte del diseño en sí. Pero la estructura de información es la base sobre la que se apoya cada pantalla que viene después, y una base mal sorteada obliga a rehacer trabajo visual que ya se dio por terminado.
